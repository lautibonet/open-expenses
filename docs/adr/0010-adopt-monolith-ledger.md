# 0010 - Adopt Monolith Ledger in place of the Quiet Register

The Quiet Register system (paper tones, small radii, a green income ink, an amber warning ramp, system fonts, and a 0.9rem body) read as gentle but visually weak: hierarchy was carried by timid size steps, income green fought the action blue for meaning, and amber made a third signal family nobody asked for. We adopted the Stitch "LedgerFlow / Rigid Minimalism" system — **Monolith Ledger** — replacing every token value in `src/styles.scss` per `docs/new-design/MIGRATION.md` §1: a monochrome surface ramp with hard black strokes and zero radius, Inter + self-hosted JetBrains Mono on a much larger type ramp, primary blue (#003ec7/#0052ff) for action and income, and a single error ramp (#ba1a1a/#ffdad6/#93000a) that absorbs warnings. ADR 0008 stands: tokens remain CSS custom properties in `styles.scss` consumed through the shared SCSS patterns; only values (and functional token names) changed, with the radius names kept compiling at value `0` and the green/amber/danger sub-ramps retired in favor of primary and error. The trade-off is deliberate: green no longer distinguishes income from interactive blue (D8 — stripes, arrows, and mono numerals carry direction instead; revisit after release), and amber warnings are darker and more alarming on the error ramp. Markup, flows, and business logic are untouched; screen restructuring follows in later tickets.
